# KINGAIBOT V1.2 Security & Execution-Layer Baseline

## English

### Purpose

KINGAIBOT V1.2 is a security-first expansion of kingai.work's long-term agent runtime. It continues the project's role as the future terminal execution layer for the KING AI intelligent-lifeform system while preserving strict approval, audit and rollback boundaries.

### Security changes driven by independent scanning

GitHub Advanced Security / CodeQL findings from the V1.1 publication were treated as engineering input rather than dismissed as scanner noise. V1.2 changes the execution path itself:

- file reads and writes use Go `os.Root` traversal-resistant filesystem operations;
- user-controlled file paths are constrained to configured read/write roots;
- symbolic-link escape and `..` traversal are regression-tested;
- path length and component-count limits bound filesystem traversal cost;
- generic HTTP access remains HTTPS-only, allowlist-based and DNS-rebinding/SSRF guarded;
- redirects may not downgrade to HTTP, use a non-standard TLS port, contain credentials, or escape the destination allowlist;
- authenticated provider, MCP and A2A calls do not automatically follow redirects;
- a global `*` HTTP destination allowlist is rejected;
- shell execution remains disabled by default and accepts only explicitly configured bare executable names when enabled;
- exact action approvals remain bound to task + tool + canonical argument hash;
- side-effect results remain durably recorded and hash-chain audited.

### V1.2 safe local execution capabilities

The execution layer now includes these filesystem capabilities:

| Capability | Purpose | Recommended default |
|---|---|---|
| `file_read` | read a bounded regular text file | ALLOW inside workspace |
| `file_stat` | inspect file/directory metadata | ALLOW inside workspace |
| `file_list` | list a bounded directory | ALLOW inside workspace |
| `file_write` | atomically write a bounded file | ASK |
| `file_mkdir` | create directory trees | ASK |
| `file_delete` | delete one file or one empty directory | ASK |
| `shell_exec` | run an explicitly allowlisted binary without a shell | DENY |

Recursive delete is intentionally not exposed as an agent tool in V1.2.

### Network capability boundaries

`http_get` is not an unrestricted browser or arbitrary socket primitive. It is constrained by scheme, port, hostname allowlist, DNS/IP validation, response-size limits, timeout and redirect policy. MCP/A2A endpoints and model providers are administrator-configured endpoints with separate credentials.

### Controlled evolution

V1.2 keeps self-improvement in proposal-only mode. The runtime may collect bounded evidence and produce evolution proposals, but production core changes must continue through source control, review, CI/security scans, signed releases and rollback-capable updates.

### Release identity

Starting with V1.2, distributable archives use the `kingaibot_...` product prefix. The CLI/runtime binary names `kingagent` and `kingagentd` remain for compatibility and may gain KINGAIBOT aliases in a future backward-compatible release.

### Validation gate

A V1.2 merge/release must pass the repository's Go 1.26.5 gates including formatting, vet, unit tests, race detection, govulncheck, native macOS/Windows tests, PowerShell parsing, Docker build, CodeQL and release artifact generation.

## 中文

### 目标

KINGAIBOT V1.2 是 kingai.work 长期智能体项目的一次“安全优先”升级。它继续作为 KING AI 智慧生命体未来终端执行层发展，同时坚持审批、审计、回滚和权限隔离边界。

### 基于独立安全扫描的实质修复

V1.1 发布后 GitHub Advanced Security / CodeQL 给出的告警没有被简单当作误报关闭。V1.2 直接修改真实执行路径：

- 文件读写改用 Go `os.Root` 抗路径穿越文件系统 API；
- 用户控制的文件路径被限制在配置的读/写根目录；
- 对符号链接逃逸和 `..` 穿越加入回归测试；
- 加入路径长度和目录层级限制，控制恶意遍历成本；
- 通用 HTTP 能力继续坚持 HTTPS、目标白名单和 DNS Rebinding/SSRF 防护；
- 重定向不得降级到 HTTP、不得切换非标准 TLS 端口、不得携带 URL 凭据、不得逃离目标白名单；
- Provider、MCP、A2A 的鉴权请求不自动跟随重定向；
- 禁止 HTTP 目标使用全局 `*` 白名单；
- Shell 仍默认关闭；即使启用，也只允许管理员明确配置的裸命令名，并且不经过 shell 解释器；
- 审批继续绑定“任务 + 工具 + 规范化参数哈希”；
- 有副作用操作继续持久化结果并进入哈希链审计。

### V1.2 安全本地执行能力

终端执行层现在扩展以下文件能力：

| 能力 | 用途 | 建议默认策略 |
|---|---|---|
| `file_read` | 读取受限大小的普通文本文件 | 工作区内 ALLOW |
| `file_stat` | 查看文件/目录元数据 | 工作区内 ALLOW |
| `file_list` | 列出受限数量的目录项 | 工作区内 ALLOW |
| `file_write` | 原子写入受限文件 | ASK |
| `file_mkdir` | 创建目录树 | ASK |
| `file_delete` | 删除单个文件或空目录 | ASK |
| `shell_exec` | 不经过 shell，直接执行显式白名单程序 | DENY |

V1.2 **故意不向智能体暴露递归删除能力**。

### 网络能力边界

`http_get` 不是无限制浏览器或任意 Socket。它受到协议、端口、主机白名单、DNS/IP 验证、响应大小、超时和重定向策略共同约束。MCP/A2A 和模型 Provider 则属于管理员显式配置、使用独立凭据的远程端点。

### 受控自进化

V1.2 继续保持 proposal-only 自进化模式。Runtime 可以收集受限证据并产生改进提案，但生产核心修改必须继续经过源码管理、审查、CI/安全扫描、签名 Release 和可回滚更新流程。

### Release 品牌

从 V1.2 开始，正式分发归档统一使用 `kingaibot_...` 前缀。为保持兼容，CLI/Runtime 二进制暂时继续使用 `kingagent` / `kingagentd`；未来可通过兼容别名逐步统一。

### 发布门禁

V1.2 合并/发布必须通过仓库 Go 1.26.5 全套门禁，包括格式、vet、单元测试、race detector、govulncheck、macOS/Windows 原生测试、PowerShell 解析、Docker 构建、CodeQL 和正式 Release 构建。
